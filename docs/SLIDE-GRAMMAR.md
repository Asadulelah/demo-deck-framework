# Slide Grammar — what each slide must contain

The deck is a product walkthrough. Each slide type below has one job. If a slide is doing two jobs, split it. If it's doing zero, cut it.

## 1. Cover

- Product name + one-line tagline. Nothing else competes.
- The app shell is already visible (dimmed or blurred behind the title works well) so the very first frame promises "you are about to see a real product."

## 2. The cost of the problem (exactly one slide)

- NOT a problem lecture. One tight frame: what the current way costs, in their numbers if you have them, in category numbers if you don't.
- A chaos view works: their current tool pile with broken connections between the tiles. Keep it to one glance.
- The moment this slide starts explaining, you've lost the format. It exists only to make the next slide land.

## 3. The reveal — "everything in one place"

- Hub view: every module of the system around a single center. This is the map the rest of the deck walks through.
- Each module tile here becomes a slide later, in the same order. The audience should feel the table of contents without reading one.

## 4-N. One app screen per module

The core of the deck. Rules per screen:

- **Same shell every time.** Sidebar + top bar identical; only the active nav item and the page content change. Inject the shell from one place so it cannot drift.
- **Dashboard goes first.** It's the hero screen: KPI cards, a live-feeling table, one alert. It sells "command center" before any feature does.
- **Realistic anonymous data** (see CRAFT-RULES on lived-in numbers).
- **Caption = module tag + one-line benefit.** Example: `QUOTES — follow-ups send themselves until the client answers.` That's the entire written explanation. You say the rest out loud.
- **Show the mechanism, not the claim.** Don't write "automated follow-up." Show the message thread inside the page with the third follow-up already sent and a reply landing. The product proves it can be done; it doesn't claim it.
- Where the human/machine split matters, add a small "You / The system" strip: the one tiny thing the user does, next to the pile of things the system does.

## The AI / assistant page

- One screen where the assistant is mid-task on the business's real (fictional) data. A chat panel next to the thing it changed. Nothing sells "it works inside your business" harder.

## Security

- Light and human. "Your data is encrypted, backed up daily, and only your team can see it." A lock badge, two or three plain-language lines. No jargon dump, no compliance wall.

## Migration

- The prospect's silent fear is "switching will hurt." One screen: what moves over, who does it (you, not them), how long. Small numbers, plain words.

## Close

- Not a "thank you" slide. The dashboard again, or the hub, with one line that assumes the future: the product with their name on it. Leave the product on screen while the conversation starts.

## The caption formula

```
MODULE TAG — one line, outcome first, mechanism implied.
```

Good: `DISPATCH — every driver's day plans itself at 6am.`
Bad: `Our dispatch module uses intelligent routing algorithms to optimize scheduling.`

The bad one explains. The good one lets the screen prove it.

## Walkthrough discipline

- Present it live. The deck is designed for narration, not for being emailed cold. If it must travel alone, the captions carry it, which is why they're outcome-first.
- Order the module screens by what the buyer feels first, not by your architecture. Pain order, not system order.
